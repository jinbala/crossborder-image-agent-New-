# 0.25.0 采集图片直接衔接 SKU 图包验收

日期：2026-10-21。Windows 0.25.0 / 扩展保持 0.5.4。对应需求 2.1 可追踪工作流、4.3 确认/恢复、COLLECT-005、SKU-001/009、WEB-TASK-001。保留原需求范围及实站边界。

## 实现

- 采集结果页新增“使用本任务图片整理图包”，只导航到原 SKU 规则编辑器，不自动开始处理。来源来自当前服务已经保存的图片，不读外部路径、不访问图片源站、不自动跨设备传图。
- GET /api/workbench/collection-jobs/:jobId/sku-pack-preview 只读校验归属、清单身份、路径/软链接/目录越界、实际字节散列及栅格解码；输出任务 ID、相对路径、原 SKU/标题、图片数和预检散列，不返回服务器绝对路径。损坏/缺失/不支持图片明确拒绝，不默默跳过。
- POST 同一路径的 sku-pack 只接受 strict confirm=true 与当前预检散列；原采集未全部成功时还需 strict confirmPartial=true，明确只处理已经收到的快照。复用现有排序、命名、角色、压缩、方图、去重和抠图规则；外部抠图仍单独明确确认，不因进入页面或拥有密钥自动调用。
- 当前沿用 SKU 单次 1–300 张、15MB/张、500MB 总量和 JPG/PNG/WebP 限制，超过限制请使用原 ZIP 下载后拆分处理，不截断或宣称支持无限图包。
- 创建前以成员、来源快照和规范化规则生成持久回执；并发/回复丢失/后端进程重启重试取得原目标，不另建图包。规则变化创建新包，原图包保留；中断时从已有 SKU 断点明确恢复，不把重放当作自动续跑。
- 新 collection_pack_transfers 表纳入工作空间备份；恢复期间禁止并发创建，旧未提交预检因工作空间世代变化拒绝，备份中已有回执可读取原结果。
- 回执在首次图包断点已落盘、任何图片处理开始之前标记 published。已进入处理的结果丢失时明确拒绝，不因清单/目录缺失自动重建或再次调用 Provider；未开始的输入准备可用原回执继续。
- 来源任务、逐图 itemId/相对路径/散列保存在图包 manifest 和恢复清单中，结果页刷新后仍有来源入口。原采集清单和图片不修改。复制到私有输入缓存后再次验散列，变化时不进入图片处理。
- 同时修复原 SKU 费用确认对字符串 true 的宽松解析，只有布尔 true 表示本次批准。手工/直接图包共用新的远程抠图只读预检：重新读取所选 Provider 的实际 origin，拒绝无效/带凭据地址，显示目标、图片数量、服务地址及未核定费用/失败重试可能计费，再由本次弹窗确认；取消不提交。Sharp/rembg 不因此请求远程预检或获得付费权限。暂停/未完成结果不冒称全部完成，没有 ZIP 时不显示假下载链接。
- 新增 19 条受控文案，词典 2,355 条；不翻译原始商品标题和 SKU。完整双语缺口仍保留。
