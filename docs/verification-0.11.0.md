# 0.11.0 本机验收记录

日期：2026-10-20。基线与未关闭项：[实施进度](./implementation-progress.md)。本版重点为扩展连接诊断修复和第二批运营页面双语；不表示 Temu 实站回传已验收。

## 扩展 0.5.2

- 不再在未配对时静默连接 4000。发送前要求明确的客户端地址/配对；仅显式选择源码开发模式时可连接无鉴权开发服务。
- 新增服务可达/身份检查，明确说明它不证明令牌仍有效。端口不通、超时、服务身份不符和配对失效分别给出建议，保留手动清单；未连接时不建任务、不读图片。
- 允许已限定的扩展来源/采集路径读取鉴权失败响应，避免 CORS 将其隐藏成 Failed to fetch；仍拒绝未经授权访问业务数据，网站和其他路径没有新增权限。
- 图片域名授权在按钮点击时、网络 await 之前请求，避免失去用户手势。拒绝授权不启动回传；不导出 Cookie、不绕过权限。
- 手动清单不再显示误导的 1/0。轮询不覆盖正在编辑的地址，也不自动清掉错误提示。

实机只读证据：当前旧客户端服务 127.0.0.1:60011 返回健康检查 200。用户明确确认“本地会话已失效”出现在 Edge 直接打开该地址后，这符合客户端 HttpOnly 本地会话保护，不是服务未启动。用户仍需在扩展中填写地址和客户端生成的配对码，然后反馈真实发送结果；没有替用户操作账号或清空清单。

## 交付与边界

包内扩展需在原稳定目录重新加载并重新配对，保持同一扩展目录才能沿用 Chrome/Edge 保存的手动清单。重启客户端后端口可能变化，必须使用新版窗口显示的地址。没有强制退出用户旧客户端或改动 Edge 登录态。

安装版尚未在干净机器安装/卸载，无 Windows 签名；模型许可/效果、实图大任务、最新官方模板导入、真实平台和发布条件仍未关闭。无商品发布、线上改价、验证码绕过、模型权重下载、公开部署或 Git 推送。

新增审计待办：建任务请求已提交但响应丢失、扩展未拿到任务 ID 时，当前 /collection-jobs/rows 尚无客户端请求幂等键。现有回归证明未连接不建任务、已知 ID 重传复用和单图幂等，不能作为未知提交结果下“绝无重复任务”的证据。后续补充该场景，不因本版诊断修复将其标记完成。
