# 0.17.0 本机验收记录

日期：2026-10-20。Windows 0.17.0 / 扩展 0.5.3。基线仍为 [开发需求](./xingya-web-client-development-requirements.md)，完整 68 项与未关闭条件见 [实施进度](./implementation-progress.md)。

## 关键修复

- 商品识别、真实审核/重新生图、远程方案抠图预览、批量真实执行/重试/恢复及真实识别压测，在 HTTP 入口先检查严格布尔 confirmPaidApi=true，再进入任务写入或 Provider；缺少、false、字符串 true、数字均返回 403。内部 mock 测试不会因此获得 HTTP 付费权限。
- 前端从只读配置取得每种服务 origin，去掉账号、路径和查询参数；无法核对来源则失败关闭。每次批准显示任务/批次、处理范围、去向及失败/自动重试也可能收费；mock/本地 Sharp/rembg 返回 confirmPaidApi=false，不自动授予真实调用权限。背景生成预检还列出其旧版抠图子步骤去向；方案抠图预览按 MATTING_PROVIDER 判断，远程需批准、本地无费用弹窗。单图原 confirmReal、真实验收三重确认继续保留。
- 队列将 mode 持久化；恢复等待在途 SKU 完成后只启动一个后续执行，避免并发恢复导致重复处理。旧记录缺 mode 时保守 mock。真实模式恢复需重新确认。
- prepare 不再将 AI 识别字段自动写为 productInfoConfirmed；识别后停在 recognized/waiting_confirm，人工保存商品后再次准备才生成平台目标/方案。移除原自动确认辅助函数。
- 修复 RealBackgroundImageProvider 中 real-test 分支不可达；受安全规则约束的主图/卖点/细节/场景可进入该分支。缺密钥回退有明确标志，不作为真实生成成功；本轮没有调用付费模型。
- 修复最终验收页 ErrorMessage 属性用错导致失败不显示；替换报告和删除问题需确认。人工报告仍只保存在当前页面/导出文件，不写任务数据库。真实验收最多 3 项工作流操作，不是服务商计费请求上限；内部重试与抠图可能增加调用。

## 双语范围与边界

新增 577 项 UI 文案，词典共 2,118 项。剩余 5 页的静态文案与显式消息迁移后，全 JSX 默认/--expressions 审计均为 0 未迁移、0 缺词条；新增全项目门禁。

这不是完整双语证明。多个动态辅助模块仍有受控标签与格式化消息需要迁移，列表见 [双语进度](./i18n-progress.md)。原始规则、报告正文、错误、日志、文件名、SKU、商品标题和用户问题记录保持原文；不能把动态 UI 标签一律冒充“业务原文”来关闭缺口。
