## 代码与复现

- 本地实际控制器仍存在时，即使持久化租约过期，也拒绝第二个执行。取消只停止后续调度，保留在途请求与锁直到结束；在途成功可以保留，但 batch 与 queue 最终仍为 cancelled，不被 waiting_confirm/partial_failed/paused 覆盖。
- 暂停后恢复显式选择 pending。原实现恢复前已改回 running，导致通过状态猜测“是否恢复”失效，已完成 SKU 会重新调度并变成 skipped。现总数和分类一致，已完成项保留，重启后仅有持久化队列时同样处理。
- 重试等待期间暂停/取消后，不再发出重试请求。运行中删除先取消并等待在途 SKU 结束，避免删完记录后旧执行又写入。
- 原 JOB_TIMEOUT 只是 Promise.race，底层请求会继续；阻塞复现中先后出现 3 次请求而第一条仍未结束。现每次执行用独立异步上下文使超时尝试失效，任务写入和后续图片计划检查该上下文。timeout_draining 日志明确等待实际请求结束，再处理失败/重试/释放锁；取消期间不会重试。Provider 已发生的费用和自身文件输出不能撤销，不冒充已中断远程请求。
- 页面在 cancelled + 锁未释放时保留提示和轮询；已暂停但仍有 runningJobs 也继续刷新。释放后停止轮询并恢复新队列入口。受控提示有中文/英文，业务文本不改写。
- 窗口截图检查发现旧版批量识别/目标/方案/生成/审核按钮未随锁禁用，现一并禁用。对应 7 类 HTTP 修改入口也在队列运行/占锁时返回可恢复的 409；付费入口仍先校验本次费用确认，不因锁检查放宽批准。
