日期：2026-10-21。Windows 0.18.0 / 扩展 0.5.3。需求对应第 4.3 节“刷新后状态不丢失”、DESK-DATA-001 / DESK-RECOVERY-001 的验收数据恢复，不更改原始 68 项范围。完整状态见 [实施进度](./implementation-progress.md)。

## 实现与安全边界

- platform.sqlite 新增 acceptance_workspaces：每成员一份当前报告、问题、人工结论、问题草稿和真实 API 普通表单参数。管理员也使用自身槽位；operator/designer 可保存，viewer 只读，support 拒绝。HTTP 会话/CSRF/角色检查保留，前端提供 expectedActorId，账号变化不把旧报告写入新成员。
- generation + revision 乐观并发；requestId + 内容散列重放丢失回执，同请求不同内容拒绝，旧版本不覆盖新版本。普通保存、模板/预填及重置互斥，生成新模板时锁定编辑区；输入期间的后台保存串行提交最新内容，不因较旧回执清除新编辑。
- 前端按成员在 sessionStorage 暂存未确认保存及后续编辑。刷新先读取服务端并检查代际/版本和关联任务权限，再重试原保存；不把缓存直接作为权限证明。冲突或损坏记录不自动丢弃/覆盖；导出副本后由用户明确重新读取。浏览器存储不可用时明确提醒，服务端保存仍可用；未保存且浏览器存储失效不保证恢复。
- confirmRealApi / confirmPaidApi / confirmNoPlatformUpload 及凭据字段不持久化，恢复时三项确认均为 false。真实调用仍走既有本次批准和费用去向预检；本轮恢复不会调用真实 API。
- 关联 task/batch 引用在保存、缓存校验和读取时校验权限；改归属后原工作区只返回不可读取状态，不返回旧业务报告。损坏/超限文档拒绝，不静默覆盖。最大 1MB、深度/节点上限；不增加全局 HTTP 请求体限制。
- 工作区进入现有 SQLite 备份/恢复，恢复后逐成员更新 generation，旧页面写入失败。重置需 confirm=true 和当前版本，只移除验收工作区，不删原任务、图片和导出文件。未向云端摘要同步添加报告正文。
